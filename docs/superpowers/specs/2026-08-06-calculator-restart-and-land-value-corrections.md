# 計算器重啟流程與公告現值換算修正

## 背景

完整操作審查發現五個可重現問題：

1. 結果頁按「重新試算」會清空同一計算器的所有數字欄位。買方費用中的代書費、銀行費、謄本份數等安全預設也被清掉，使用者重新填完主要金額後，最後只看到不易定位的驗證錯誤。
2. 公告土地現值工具把「元／平方公尺」換算成「元／坪」時使用乘以 0.3025，方向相反，連帶讓總額約低估 10.9 倍。
3. 尚未填入前次移轉現值時，頁面把空白當成 0，會把本次公告現值總額誤顯示成土地價格差額。
4. 數字欄位輸入非數字內容後離開欄位，格式化流程會先把內容改成 0，使精靈無法指出原始輸入無效。
5. 貸款與青安計算器重新試算時，文字欄會恢復預設薪資，但對應滑桿仍保留前一次數值。

## 設計決策

- 保留「清空」與「重新試算」的語意差異：
  - 清空仍移除所有輸入。
  - 重新試算回到第一步並恢復該計算器的安全預設值，不立即跳回結果頁。
- 精靈每一步離開前，用與最終計算相同的嚴格數字解析檢查空白與非數字內容，避免錯誤延後到結果頁才出現。
- 數字格式化只處理可正確解析的內容；非數字原值維持不變，交由欄位驗證顯示錯誤。
- 恢復預設值後同步所有薪資滑桿，確保滑桿、文字欄與試算值一致。
- 公告現值換算採用：
  - 每坪單價 = 每平方公尺單價 ÷ 0.3025。
  - 土地總額 = 土地面積（平方公尺）× 每平方公尺單價。
- 將「坪數換算」結果名稱改成「總額」，避免把總價誤認成每坪單價。
- 前次移轉現值未填時，前次總額與價格差額顯示為「尚未計算」；補填後才顯示差額。

## 不變範圍

- 不更動房地合一稅率、青安貸款政策、買方 2% 服務費與貸款攤還公式。
- 不加入 Node、後端 API 或第三方框架。
- 不部署 GitHub Pages，也不搬遷 VPS；完成驗證後再另行處理。

## 驗證案例

- 買方預設案例完成試算後按重新試算，第一步金額與進階費用預設都必須恢復。
- 清空後若目前步驟有空白數字欄位，不得進到下一步。
- 東區竹篙厝段 0630-0556：43 m²、29,600 元／m²，應顯示每坪 97,851 元、公告土地現值總額 1,272,800 元。
- 四個計算器與兩個土地工具在手機、桌機均無橫向溢位或主控台錯誤。
